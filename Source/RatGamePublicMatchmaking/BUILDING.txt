Rat Game Public Matchmaking v0.2.0 | Madara | MIT

Requires .NET SDK 10, your own installed Steam Rat Game and BepInEx 5.4.23.5.
NuGet.Config clears remote feeds. No external package downloads are required
with SDK targeting packs and BepInEx core assemblies present locally.

From the source directory:
  build.cmd
or with explicit references:
  build.cmd "C:\path\to\rat game" "C:\path\to\BepInEx\core"

The script builds the mod, runs offline tests, and runs the Mono.Cecil validator
against actual installed assemblies. Fixed SHA256 contracts identify the
investigated game build. Reinvestigate after an update; do not substitute stubs.

Individual commands:
  dotnet build src/RatGamePublicMatchmaking.csproj -c Release -p:RatGameDir="C:\path\to\rat game"
  dotnet run --project tests/SafetyTests.csproj -c Release
  dotnet run --project validation/Validation.csproj -c Release -p:CecilPath="C:\path\to\BepInEx\core\Mono.Cecil.dll" -- . "C:\path\to\rat game\Rat Game_Data\Managed" "C:\path\to\BepInEx\core"

The plugin targets netstandard2.1. References use Private=false: only the mod DLL
belongs in plugin output. Mono.Cecil is open-source validator tooling from
BepInEx. Do not distribute game reference DLLs, IL/hierarchy dumps, screenshots,
private logs or local banlists. No new artistic assets are created or bundled.

build.cmd does not install, create a ZIP, push, or publish anything. Output:
  src/bin/Release/netstandard2.1/RatGamePublicMatchmaking.dll
The installed/released 0.1.0 beta stays separate. This workspace has no Git
checkout or executable; use this isolated development directory. For integration,
apply the reviewed source changes to a v0.2.0 host-moderation branch in an actual
checkout. CHANGES.txt maps changed and added files. Do not replace beta releases.

validation/SmokeTest.ps1 is phased single-account runtime tooling. Requires Steam
and a closed game before installation/restoration. It verifies and backs up the
installed beta/configuration, stages the validated development DLL, and temporarily
disables Public Hosting and NativeUiTools. It never launches the game executable,
kills a game process, or swaps a DLL while Rat Game is running. No banlist is edited.

Run the harness's independent offline checks first:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File validation/SmokeTest.Tests.ps1
Then use these phases for an intentional local smoke test:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File validation/SmokeTest.ps1 -Action Prepare
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File validation/SmokeTest.ps1 -Action Launch -WaitSeconds 20
If automation produces no game process, use the normal Steam Library Play button.
Once Steam is ready, use the game's normal Host action and wait in the lobby.
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File validation/SmokeTest.ps1 -Action Observe -WaitSeconds 30
Quit Rat Game normally when observations are complete, then restore:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File validation/SmokeTest.ps1 -Action Restore

The execution-policy option applies to that PowerShell process only. The session
path is tracked in artifacts/active-smoke-session.txt until restoration succeeds.
An explicit -Session path can inspect a completed session after that pointer is
removed. Session.json and timestamped Events.jsonl keep candidate/backup hashes,
launch requests, process IDs, fresh-log initialization/readiness/hosting events,
and independent PrimaryErrors/CleanupErrors arrays. Current runs cannot borrow
readiness from an older log. A failed launch leaves the candidate staged for a
manual Steam launch; it does not silently restore or close the game. Always finish
with Restore and verify both original hashes. The live BepInEx log is retained;
its pre-test copy is backed up separately. Private smoke evidence is ignored.

This verifies local startup/hosting only, not remote moderation. See
inspection/RUNTIME-STATUS.txt for the actual results and remaining live checks.

NativeUiTools defaults OFF. Diagnostic commands are strictly enumerated local
commands, with no arbitrary code execution or network endpoint. New moderation
commands exercise actual native buttons. Do not include private smoke backups
or evidence in a source distribution. Historical RuntimeVerification.cs concerns
only v0.1 evidence and cannot establish v0.2 moderation verification.

Current test scope: see the release Validation/TEST-SUMMARY.txt, README.md and
inspection/LIVE-TEST-MATRIX.txt. Madara reports successful Kick/Ban/Unban and an
organic public session with Eric. Do not infer unreported cases from that report.
Offline simulations, one-player hosting and screenshots remain separate evidence.

Stable release preparation changed only informational/Windows product metadata
and the startup version text from 0.2.0-dev.1 to 0.2.0. release-tools/CompareStable.ps1
compares source, normalized full assembly bytes and all Windows resource values
against the preserved tested DLL. Its local preserved evidence is not distributed.
